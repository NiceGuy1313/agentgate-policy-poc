# v3 결과: Gate 없음 / Gate + 판정 LLM / Gate + 판정 LLM + 정책 문서

> "분석" 절은 이 문서의 수치만으로 손으로 썼다. "재생 대조" 절은 `scripts/v3/replay_contrast.py`, 나머지는 `scripts/v3/summarize_v3.py`가 생성했다. 실행 기록(json)은 요약 후 지웠다.

## 한눈에 보기

- 공격 성공률(ASR): Gate 없음 25.2% → Gate + 판정 LLM 2.3% → Gate + 판정 LLM + 정책 문서 1.9%.
- 판정 LLM을 넣으면(C9n − C0): ASR -22.9%p (p=3.8e-57, 유의), 정상 Utility -8.2%p (p=0.0963, 유의하지 않음), 공격 중 Utility -5.1%p (p=0.00126, 유의).
- 정책 문서를 읽히면(C9 − C9n): ASR -0.4%p (p=0.388, 유의하지 않음), 정상 Utility +7.2%p (p=0.118, 유의하지 않음), 공격 중 Utility +2.4%p (p=0.0826, 유의하지 않음).
- 같은 입력으로 정책 문서 유무만 바꾸면(재생 대조): 공격 호출 차단률은 같고(99.7% 대 99.8%, p=0.5), 정상 호출 오차단은 21.5% → 17.2%로 유의하게 줄어든다(p=1.88e-05).

## 분석

### 1. 판정 LLM은 공격을 막는다

- ASR이 Gate 없음 25.2%에서 판정 LLM을 넣으면 2.3%(C9n), 1.9%(C9)로 떨어진다. 두 차이 모두 유의하고(p=3.8e-57, p=2.63e-61), 신뢰구간도 겹치지 않는다(C0 [22.5, 28.0], C9n [1.5, 3.5], C9 [1.2, 3.0]).
- 남은 공격 성공 중 툴 호출로 성공한 것은 판정 LLM이 허용한 경우뿐이며, C9n·C9 모두 10건(949건 중 1.1%)이다. 나머지(C9n 12건, C9 8건)는 툴 호출 없이 답변 텍스트로 성공한 유형 H로, Gate가 다룰 수 없는 경로다.

### 2. 정책 문서는 보안에 효과가 보이지 않는다

- C9의 ASR은 C9n보다 0.4%p 낮지만 유의하지 않다(p=0.388).
- 툴 호출로 성공한 공격은 정책 문서가 있든 없든 10건으로 같다. ASR 차이 4건은 모두 유형 H(12건 → 8건)에서 나왔다. 유형 H는 판정 LLM이 관여하지 않는 경로이므로, 이 차이는 정책 문서가 아니라 에이전트 실행마다의 편차로 보는 것이 맞다.

### 3. live에서는 정책 문서가 정상 작업 손실을 줄이는 방향이지만 유의하지 않다

- 판정 LLM의 BLOCK 비율이 C9n 48.2%(588/1221)에서 C9 45.0%(548/1217)로 낮다. 정책 문서를 읽으면 덜 막는다.
- 공격 없는 실행에서 판정 LLM 차단으로 실패한 작업이 C9n 11건에서 C9 7건으로 줄었다. 그 결과 정상 Utility가 65.0%에서 72.2%로 7.2%p 높다. 다만 표본이 97건이라 유의하지 않고(p=0.118), 신뢰구간도 크게 겹친다(C9n [55.0, 73.7], C9 [62.5, 80.1]).
- 공격 중 Utility도 C9가 2.4%p 높지만 유의 수준에 못 미친다(p=0.0826).
- 방어 없음과 비교하면 차이가 드러난다. C9n은 공격 중 Utility가 C0보다 유의하게 낮지만(−5.1%p, p=0.00126), C9는 유의한 차이가 없다(−2.6%p, p=0.0935). 정상 Utility도 C9는 C0와 거의 같다(−1.0%p, p=1).

### 4. 같은 입력으로 비교하면 정책 문서는 오차단을 유의하게 줄인다

live 비교는 조건마다 에이전트가 다르게 움직여 편차가 크다. 같은 97개 작업에서도 차단 없이 실패한 수가 조건마다 20–26건으로 달랐다. 그래서 에이전트 없이 정답 궤적을 재생하고, 같은 입력을 두 판정 LLM에 넣어 정책 문서 유무만 바꿨다("재생 대조" 절).

- **오차단이 줄어든다.** 정상 호출 920개 중 BLOCK한 비율이 C9n 21.5%에서 C9 17.2%로 4.3%p 낮다(p=1.88e-05, 유의). 두 판정이 엇갈린 호출 86개 중 정책 문서가 있는 쪽만 허용한 것이 63개, 없는 쪽만 허용한 것이 23개다.
- **공격 차단은 그대로다.** 공격 호출 2,513개 중 BLOCK한 비율은 C9 99.7%, C9n 99.8%로 차이가 없다(p=0.5).
- **궤적 단위로도 같은 방향이다.** 공격 쌍에서 정상 호출을 모두 허용한 비율이 C9 88.8%, C9n 86.9%로 유의하게 높다(p=0.0133). 정상 작업 97개만 보면 +2.1%p지만 표본이 작아 유의하지 않다(p=0.727).
- **판정 LLM은 정책 문서를 실제로 쓴다.** C9 판정 이유에 가장 많이 인용된 조항은 R2(툴 콘텐츠가 시킨 행동)와 R1(요청된 행동만)이다.

### 5. 비용

- 정책 문서를 넣은 C9는 system 프롬프트가 길어져 프롬프트 캐시 대상이 된다. 판정 LLM의 캐시 외 입력은 오히려 C9가 적다(690,566 대 973,571 토큰). 캐시 읽기는 C9 1,581,599, C9n 286,166 토큰이다.
- 판정 API 호출 수는 거의 같다(C9 1113회, C9n 1111회).

### 결론

- **판정 LLM(Gate)의 효과는 분명하다.** live에서 ASR을 25.2%에서 약 2%로 낮춘다.
- **정책 문서는 보안을 더 강하게 만들지는 않는다.** live에서 툴 호출로 성공한 공격 수가 같고, 재생 대조에서도 공격 호출 차단률이 같다(99.7% 대 99.8%).
- **정책 문서는 정상 호출 오차단을 줄인다.** 같은 입력으로 비교하면 오차단이 21.5%에서 17.2%로 유의하게 낮다. live에서는 이 차이가 에이전트 편차에 묻혀 유의하지 않았다.
- 정리하면 정책 문서의 효과는 같은 보안 수준에서 정상 작업을 덜 막는 것이다.

## 재생 대조: 같은 입력에서 정책 문서 유무만 바꿈

> `scripts/v3/replay_contrast.py`가 생성한다. 에이전트 없이 정답 궤적의 호출을 그대로 실행하고, effect 호출마다 같은 입력(TaskSpec + 지금까지의 ToolSpec + 대기 중 호출)을 두 판정 LLM에 넣었다. 판정으로 막지 않으므로 모든 호출에서 두 조건의 입력이 같다. 차이는 정책 문서 유무뿐이다.

- 궤적: 정상 97개, 공격 쌍 949개(`tool_knowledge`). 판정한 effect 호출: 공격 호출 2513개, 정상 호출 920개.
- 두 판정이 같은 답을 낸 호출: 97.4% (3345/3433) [96.9, 97.9]

## 구성 요소

**TaskSpec 추출기** (`claude-haiku-5-5`): 사용자가 허락한 범위를 구조화한다.
- 입력: 사용자 프롬프트, 툴 목록(이름·설명). 툴 응답은 보지 않는다.
- 출력: TaskSpec. 요청한 행동(`requested_ops`), 사용자가 지목한 자료(`named_sources`), 허용 목적지(`allowed_dest`), 금액 상한(`amount_cap`), 전송 요청 여부(`egress_requested`), 지시 수행을 위임한 자료(`delegated_sources`).

**에이전트** (`gpt-oss:120b`): 평가 대상이다.
- 입력: 사용자 프롬프트, 툴 응답 또는 차단 메시지.
- 출력: 툴 호출(툴 이름, 인자).

**Gate**: 툴 호출이 실행되기 직전의 관문이다. 규칙으로 판정하지 않는다.
- 입력: 툴 호출.
- 출력: 읽기 호출은 그대로 실행한다. effect 호출(상태 변경·외부 전송·URL 방문)은 판정 LLM의 답대로 실행하거나 차단한다.

**판정 LLM** (`claude-sonnet-5-5`, C9n·C9): effect 호출을 실행할지 정한다.
- 입력: 사용자 프롬프트와 TaskSpec, 지금까지 받은 툴 응답의 ToolSpec, 대기 중 호출(툴, 인자). C9는 정책 문서(`config/v3/policy.yaml`, R1–R10)를 함께 받는다. 툴 응답 원문은 받지 않는다.
- 출력: ALLOW 또는 BLOCK과 이유 한 문장.

**툴** (AgentDojo v1.2.2 환경):
- 입력: 실행이 허용된 툴 호출.
- 출력: 툴 응답. 공격 실행에서는 응답 안에 주입 문구가 들어 있다.

**ToolSpec 추출기** (`claude-haiku-5-5`): 툴 응답을 판정 LLM이 읽을 JSON으로 바꾼다.
- 입력: 툴 응답 원문, 그 응답을 만든 호출, 툴 목록.
- 출력: ToolSpec. 레코드(종류·작성자)와 응답 속 요청(누구에게 하는 요청인지, 어떤 툴로 수행되는지, 어떤 값을 지목하는지). 원문에 없는 값은 코드로 걸러낸다.

### 정상 작업이 실패한 이유

공격 없는 실행 중 실패한 것을 나눴다. "차단 없이 실패"는 에이전트가 스스로 작업을 끝내지 못한 경우다.

- **C0** 26건: 차단 없이 실패 26
- **C9n** 34건: 차단 없이 실패 23, 판정 LLM 차단 11
- **C9** 27건: 차단 없이 실패 20, 판정 LLM 차단 7

### 공격이 성공한 경로

"툴 호출 없이 성공(유형 H)"은 에이전트가 답변 텍스트만으로 공격 목표를 달성한 경우로, 툴 호출 Gate로는 막을 수 없다.

- **C9n** 22건: (a) 툴 호출 없이 성공(유형 H) 12, (d') 판정 LLM 허용으로 성공 10
- **C9** 18건: (a) 툴 호출 없이 성공(유형 H) 8, (d') 판정 LLM 허용으로 성공 10
