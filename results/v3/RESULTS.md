# v3 결과: 판정 LLM이 모든 effect 호출을 판단

> `scripts/v3/summarize_v3.py --run results/v3/live/full_tk_gpt-oss_120b`가 생성한다. 손으로 고치지 않는다. 실행 기록(json)은 요약 후 지웠다.

## 구성

- 에이전트 `gpt-oss:120b`, 공격 `tool_knowledge`, AgentDojo v1.2.2, 조건마다 공격 없음 97건 + 공격 949건.
- TaskSpec `claude-haiku-5-5`, ToolSpec `claude-haiku-5-5`, 판정 LLM `claude-sonnet-5-5`. 정책: `config/v3/policy.yaml`(gate v31).

| 조건 | 구성 |
|---|---|
| C0 | 방어 없음 (Gate audit) |
| C8 | v3.1 Gate, 모든 effect·엔진 플래그 호출→판정 LLM v3(정책 문서 전체, 최종 판단) |
| C8b | v3.1 Gate만(판정 LLM 없음), ESCALATE→BLOCK |
| C8n | C8과 같고 판정 LLM에 정책 문서를 주지 않음 |

## 핵심

- 세 방식 모두 ASR을 C0 24.7%에서 C8b 0.9%, C8 1.4%, C8n 2.1%로 낮췄다.
- 판정 LLM(C8 − C8b): 공격 중 Utility +6.6%p (p=1.89e-06, 유의), ASR +0.4%p (p=0.344, 유의하지 않음), 정상 Utility +5.2%p (p=0.302, 유의하지 않음).
- 정책 문서(C8 − C8n): ASR -0.7%p (p=0.0654, 유의하지 않음), 공격 중 Utility +1.5%p (p=0.261, 유의하지 않음), 정상 Utility -2.1%p (p=0.754, 유의하지 않음).
- 정상 Utility는 C0 81.4% 대비 C8 66.0%, C8n 68.0%, C8b 60.8%.
